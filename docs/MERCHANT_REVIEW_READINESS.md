# TTALKAK PG 심사 준비

현재 상태: **심사 준비 중 · 실결제 비활성**. 이 문서는 승인 또는 심사 완료를 의미하지 않는다.

## 홈페이지에서 확인 가능한 내용

- `/service.html`: AI 프롬프트 개선 SaaS의 기능, FREE/LIGHT/STANDARD/PRO 가격과 월 제공 횟수, 회원 전용 구매, 결제 승인 후 제공, 실물 배송 없음, 결제일 기준 1개월 이용기간, 해지·환불 링크.
- `/pricing`: 요금제 가격·사용량. 운영 환경의 구매 버튼은 계속 비활성이다.
- `/refund-policy.html`: 7일 전액 환불과 이후 미사용 횟수 비례 정산 등 정책 전문.
- `/terms.html`: 계정, 서비스, 구독, 갱신·해지·환불, 콘텐츠와 장애 관련 이용약관.
- 모든 빌드된 페이지 하단에 공개 사업자 정보와 안내 링크를 표시한다. 앱 재렌더링으로 하단 정보가 사라지지 않도록 앱 바깥에 둔다.

## 공개 사업자 정보

원본은 `prompt-hub-web-frontend/public-merchant.json` 한 곳이다. 빌드가 HTML로 이스케이프한 값을 각 페이지 하단에 반영한다. 확인된 상호 딸깍, 대표자 남지원, 사업자등록번호만 기입했다. 주소·고객문의 이메일·전화번호·신고번호는 아직 사용자 확인 전이다. 비어 있는 항목은 **확인 후 게시 예정**으로 표시하고, 정보가 모두 갖춰진 것처럼 안내하지 않는다.

계정 이메일로 일시 제시되었다가 철회된 개인·학교 이메일은 공개 정보나 계정에 사용하지 않는다. 공개 연락처는 별도로 사용자의 지정을 받아야 한다.

## 이메일 없는 심사용 일반 회원

`MerchantReviewAccountInitializer`는 일반 가입 API의 이메일 필수 규칙을 변경하지 않고, 운영자가 명시적으로 켠 경우에만 `ttalkak_review`를 만든다.

- 기본값: `MERCHANT_REVIEW_ACCOUNT_ENABLED=false`.
- 생성할 때만 `MERCHANT_REVIEW_ACCOUNT_ENABLED=true`와 `MERCHANT_REVIEW_ACCOUNT_PASSWORD`를 설정한다. 비밀번호는 저장소에 넣지 않고 배포 환경의 비밀 변수로 전달한다.
- 생성 결과는 LOCAL/USER/활성/미차단이며 이름은 심사 계정 표식이다. 이메일·전화·생년월일은 NULL이다. 결제키·유료 이용권·관리자 권한은 부여하지 않는다.
- 동일 아이디가 이미 존재하면 일치하는 일반 심사 계정에 대해서만 아무 변경 없이 종료한다. 개인 연락처, 다른 비밀번호, 관리자·탈퇴·차단 상태가 있으면 시작을 실패시키며 기존 계정을 변경하거나 삭제하지 않는다. 활성화 전 아이디 사용 여부를 확인해야 한다.
- 승인·배포 후 생성하고 로그인과 USER 권한을 확인한 다음, 생성 플래그를 false로 바꾸고 생성용 비밀 변수를 제거한다. 이후의 비밀번호 변경은 정상 회원 절차로 한다.
- 이메일이 없어 이메일 계정 복구를 사용할 수 없다. 심사 후 계정 정리는 운영자가 담당한다.

작성 시점에 운영 서버의 `/api/auth/check-user-id?userId=ttalkak_review`가 available=true를 반환했다. **아직 운영 계정은 생성하지 않았다.**

## 판매·심사 완료 전 남은 항목

1. 사업자등록증과 일치하는 주소 및 실제 고객문의 채널을 공개한다. 개인정보 처리방침은 현재 처리 항목·보유기간·처리위탁·국외이전·정보주체 권리와 연락처를 확인하여 별도로 확정·게시해야 한다. 없는 정보를 임의 작성하지 않는다.
2. 기존 체크박스의 개인정보 수집·이용 고지와 실제 처리방침을 일치시키고 링크를 제공한다. 현재 페이지 추가만으로 개인정보 고지가 완성된 것은 아니다.
3. 담당자가 결제 경로를 확인할 방법을 협의한다. 운영 서버를 test로 전환하거나 준비 중 버튼을 구매 가능으로 위장하지 않는다. 승인된 코드로 **별도 DB와 테스트 키만 사용하는 심사용 환경**을 준비하면 기존 `BILLING_MODE=test` 및 프론트 테스트 미리보기에서 실제 테스트 결제 흐름을 검증할 수 있다. 별도 환경을 아직 생성하지 않았다.
4. 토스 신청 분류는 실제 상품인 소프트웨어업/SaaS/웹서비스로 설명하고, 월 구독과 요청 횟수를 숨기지 않는다. 기존 입점 제한 사유·재심사 가능 여부는 토스 확인이 필요하다.
5. 정책상 부분·업그레이드 환불과 실제 PG 취소·권한 대사 처리, 라이브 연동을 완료·검증한 후 판매한다. 심사 계정 제공이나 사업자등록만으로 실결제가 준비된 것은 아니다.

PR #57은 팀원 재검토·승인 후 병합한다. 운영 서비스의 소스 브랜치를 미승인 PR로 바꿔 배포하지 않는다.
