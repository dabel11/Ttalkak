# TTALKAK PG 심사 준비

현재 상태: **심사 준비 중 · 실결제 비활성**. 이 문서는 승인 또는 심사 완료를 의미하지 않는다.

## 홈페이지에서 확인 가능한 내용

- `/service.html`: AI 프롬프트 개선 SaaS의 기능, FREE/LIGHT/STANDARD/PRO 가격과 월 제공 횟수, 회원 전용 구매, 결제 승인 후 제공, 실물 배송 없음, 결제일 기준 1개월 이용기간, 해지·환불 링크.
- `/pricing`: 요금제 가격·사용량. 운영 환경의 구매 버튼은 계속 비활성이다.
- `/refund-policy.html`: 7일 전액 환불과 이후 미사용 횟수 비례 정산 등 정책 전문.
- `/terms.html`: 계정, 서비스, 구독, 갱신·해지·환불, 콘텐츠와 장애 관련 이용약관.
- `/privacy-policy.html`: 실제 수집 항목, 탈퇴 후 남는 데이터와 외부 AI 처리 구조를 명시한 검토본. 계약·국외이전·삭제 주기 확인 전에는 확정 정책으로 취급하지 않는다.
- `/merchant-review.html`: 테스트 환경 로그인부터 요금제·등록·내역 확인까지의 경로 안내.
- 모든 빌드된 페이지 하단에 공개 사업자 정보와 안내 링크를 표시한다. 앱 재렌더링으로 하단 정보가 사라지지 않도록 앱 바깥에 둔다.

## 공개 사업자 정보

원본은 `prompt-hub-web-frontend/public-merchant.json` 한 곳이다. 빌드가 HTML로 이스케이프한 값을 각 페이지 하단에 반영한다. 상호 딸깍, 대표자 남지원, 사업자등록번호와 사용자 승인 고객문의 전화·이메일을 기입했다. 주소는 공개 승인을 받지 않아 공란이며, 신고번호는 확인 전이다. 비어 있는 항목은 **확인 후 게시 예정**으로 표시하고, 정보가 모두 갖춰진 것처럼 안내하지 않는다. 하단 삽입 표식이 없거나 중복되면 빌드를 실패시킨다.

계정 이메일로 일시 제시되었다가 철회된 개인·학교 이메일은 공개 정보나 계정에 사용하지 않는다. 공개 연락처는 별도로 사용자의 지정을 받아야 한다.

## 이메일 없는 심사용 일반 회원

`MerchantReviewAccountInitializer`는 일반 가입 API의 이메일 필수 규칙을 변경하지 않고, 운영자가 명시적으로 켠 경우에만 `ttalkak_review`를 만든다.

- 기본값: `MERCHANT_REVIEW_ACCOUNT_ENABLED=false`.
- 생성할 때만 `MERCHANT_REVIEW_ACCOUNT_ENABLED=true`와 `MERCHANT_REVIEW_ACCOUNT_PASSWORD`를 설정한다. 비밀번호는 저장소에 넣지 않고 배포 환경의 비밀 변수로 전달한다.
- 생성 결과는 LOCAL/USER/활성/미차단이며 이름은 심사 계정 표식이다. 이메일·전화·생년월일은 NULL이다. 결제키·유료 이용권·관리자 권한은 부여하지 않는다.
- 동일 아이디가 이미 존재하면 일치하는 일반 심사 계정에 대해서만 아무 변경 없이 종료한다. 이름 표식, 이메일·전화·생년월일 없음, 비밀번호·일반 회원·활성·미차단 상태를 확인한다. 일치하지 않거나 비밀번호 설정이 잘못되면 경고를 남기고 생성을 생략하며, 백엔드 시작이나 기존 계정을 변경하지 않는다. 저장 시 고유키 충돌도 경고 후 생략한다. 활성화 전 아이디 사용 여부와 생성 후 로그인은 별도로 확인해야 한다.
- 승인·배포 후 생성하고 로그인과 USER 권한을 확인한 다음, 생성 플래그를 false로 바꾸고 생성용 비밀 변수를 제거한다. 이후의 비밀번호 변경은 정상 회원 절차로 한다.
- 이메일이 없어 이메일 계정 복구를 사용할 수 없다. 심사 후 계정 정리는 운영자가 담당한다.

작성 시점에 운영 서버의 `/api/auth/check-user-id?userId=ttalkak_review`가 available=true를 반환했다. **아직 운영 계정은 생성하지 않았다.**

## 판매·심사 완료 전 남은 항목

1. 사업자등록증과 일치하는 주소 공개 방법을 사용자와 결정한다. 고객문의 채널은 사용자 승인 값을 반영했다. 개인정보 처리방침은 현재 처리 항목·보유기간·처리위탁·국외이전·정보주체 권리와 연락처를 확인하여 별도로 확정·게시해야 한다. 없는 정보를 임의 작성하지 않는다.
2. 가입 동의에서 약관·개인정보 수집 안내를 새 창으로 열 수 있다. 신규 웹 가입 화면에서 전화번호·생년월일 입력을 제거했다. 호환 API와 기존 저장 데이터는 유지되므로 선택 항목 처리·동의는 추가 확정이 필요하다. 탈퇴 시 생년월일도 비운다. 페이지 추가만으로 개인정보 고지가 완성된 것은 아니다.
3. 담당자가 결제 경로를 확인할 방법을 협의한다. 운영 서버를 test로 전환하거나 준비 중 버튼을 구매 가능으로 위장하지 않는다. 승인된 코드로 **별도 DB와 테스트 키만 사용하는 심사용 환경**을 준비하면 기존 `BILLING_MODE=test` 및 프론트 테스트 미리보기에서 실제 테스트 결제 흐름을 검증할 수 있다. 별도 환경을 아직 생성하지 않았다.
4. 토스 신청 분류는 실제 상품인 소프트웨어업/SaaS/웹서비스로 설명하고, 월 구독과 요청 횟수를 숨기지 않는다. 기존 입점 제한 사유·재심사 가능 여부는 토스 확인이 필요하다.
5. 정책상 부분·업그레이드 환불과 실제 PG 취소·권한 대사 처리, 라이브 연동을 완료·검증한 후 판매한다. 심사 계정 제공이나 사업자등록만으로 실결제가 준비된 것은 아니다.

PR #57은 팀원 재검토·승인 후 병합한다. 운영 서비스의 소스 브랜치를 미승인 PR로 바꿔 배포하지 않는다.


## 독립된 테스트 결제 환경 실행

`docker/compose.merchant-review.yml`은 운영 DB·RAG·관리자 계정을 연결하지 않는 **결제 전용 로컬 환경**이다. AI 서버가 포함되지 않으므로 AI 기능 자체의 심사용 시연 환경을 대신하지 않는다. MySQL과 별도 볼륨, backend, web만 생성하며 웹 포트는 localhost:4180에만 공개한다. 외부 심사자가 접근할 공개 HTTPS 환경은 아직 개설하지 않았다.

1. `.env.merchant-review.example`을 `.env.merchant-review`로 복사한다. 실제 값 파일은 git에서 제외한다.
2. 별도 DB 암호와 32바이트 이상 Base64 JWT 비밀값, 토스 `test_ck_` / `test_sk_` 테스트 키를 환경 파일에 설정한다. 운영 DB 암호·JWT·라이브 키를 복사하지 않는다.
3. 계정 생성 시에만 `MERCHANT_REVIEW_ACCOUNT_ENABLED=true`와 생성용 비밀번호를 설정한다.
4. 저장소 루트에서 `docker compose --env-file .env.merchant-review -f docker/compose.merchant-review.yml up --build -d`를 실행한다. `http://localhost:4180/merchant-review.html`에서 경로를 확인한다.
5. 실제 로그인·테스트 카드 등록·테스트 결제·내역·취소를 확인하고 생성 플래그를 false로 바꾼 뒤 생성용 비밀번호 변수를 제거하고 backend를 재생성한다. 플래그 해제만으로 계정이 삭제되지는 않는다.

웹 빌드 인수 `TTALKAK_BILLING_PREVIEW_ENABLED`는 기본 false이며 true/false 이외 값은 빌드 실패한다. 해당 인수는 테스트 UI만 연다. backend의 `BILLING_MODE=test`, 테스트 키 검증과 `BILLING_STORE_SCOPE=test:merchant-review`가 별도로 적용된다. 운영 Docker 빌드는 기존대로 미리보기를 켜지 않는다. Docker 설정 검증은 CI에 포함하지만, 키 없는 환경에서 실제 토스 결제를 검증했다고 기록하지 않는다.

## Google 실제 가입·로그인

- 브라우저는 `/api/auth/google/config`에서 **공개 Client ID만** 읽고 Google Identity Services 공식 버튼을 띄운다. 설정 누락·SDK 오류·서버 인증 실패 시 데모 계정을 부여하지 않는다. 전역 ID 토큰 주입 경로를 제거했다.
- Google에서 받은 현재 ID 토큰을 POST 본문으로 전달하고 backend가 발급자·대상·유효기간·인증 이메일을 검증한다. 최초 가입은 약관·개인정보 동의가 있어야 일반 회원으로 저장한다. 가입 후 같은 Google subject로 로그인하면 기존 계정과 권한을 재사용한다. 동일 이메일이라는 이유만으로 로컬 계정에 연결하지 않는다.
- Google 회원탈퇴는 Google Identity Services에서 새 ID 토큰을 받은 후 최종 확인 모달을 거쳐 탈퇴 API에 전달한다. 로그인 API로 재가입하거나 로컬 비밀번호를 요구하지 않는다.
- 최초 로그인에서 가입 동의가 필요하면 가입 화면으로 안내한다. Google 가입에는 로컬 아이디·비밀번호 필드를 채울 필요 없이 동의 후 Google 버튼으로 진행한다. 기존 회원 재로그인에는 최초 가입 동의를 반복 요구하지 않는다.
- 운영 backend에는 GOOGLE_CLIENT_ID 변수 이름이 존재한다. 실제 값과 Google 콘솔의 허용 JavaScript 출처·동의 화면 상태는 아직 확인하지 못했다. 운영 웹 주소 `https://web-production-a82d94.up.railway.app` 및 실제 사용하는 사용자 웹 도메인을 콘솔에 등록하고 배포 후 Google 계정으로 가입 → 새로고침 → 로그아웃 → 재로그인을 확인해야 한다. Client Secret은 브라우저에 필요하지 않다.
- 독립 결제 테스트 compose에는 Google Client ID를 주입하지 않는다. 이메일 없는 심사 계정을 Google 계정으로 바꾸지 않는다.

## AI 담당자가 확정할 사실

현재 운영 로그로 Gemini 주 공급자, Groq 대체 공급자, Jina 재정렬과 Railway 미국 서부 배치를 확인했다. 다음은 코드나 변수 이름만으로 추정하지 않는다.

- Gemini 프로젝트의 활성 Cloud Billing 연결 여부, 공급자 데이터 보유·처리 국가, 만 18세 미만 이용 관련 약관과 대상 이용자 설계.
- Groq Zero Data Retention 설정 및 예외 로그 보유 조건.
- Jina의 현재 Elastic DPA에 따른 수탁자·처리 국가·보유기간·연락처.
- Railway/메일 공급자의 수탁·국외이전 항목, 운영 로그·백업·탈퇴 데이터 삭제 주기와 실행 담당자.

공식 확인 자료: https://ai.google.dev/gemini-api/terms , https://console.groq.com/docs/your-data , https://jina.ai/legal/ , https://railway.com/legal/dpa . 운영 메일 변수에 AUTH_MAIL_TRANSPORT/RESEND_API_KEY 이름은 존재하나 실제 활성 공급자는 확인 전이다.


## 졸업프로젝트 시연 범위와 실판매 구분 (2026-10-13)

공개 사이트는 요금제 가격·제공 횟수를 안내하면서 무료 체험으로 연결한다. 유료 구독을 판매하지 않는다는 안내를 유지하며, 비활성 구매 버튼의 반복적인 '준비 중' 문구는 사용하지 않는다. 별도 테스트 환경에서는 결제·갱신·환불 흐름을 검증할 수 있다. 테스트 구현과 CI 결과는 실제 PG 입점이나 운영 결제 검증을 대신하지 않는다. 졸업 평가의 필수 범위는 지도교수·평가 기준으로 확인한다.

실판매를 진행할 경우 토스 공식 가이드는 홈페이지 하단에 사업자등록증상의 사업장 주소 기재를 요구한다. 현재는 주소 비공개 결정을 유지하며, 집 주소 공개 또는 등록 주소 정정에 대한 사용자의 결정 전에는 추가하지 않는다.
