# 검색 근거가 없는 첫 요청의 개선 처리

## 원인과 변경

기존 RAG `/query`는 기법 검색 결과와 history가 모두 비어 있으면 생성기를 호출하기
전에 404를 반환했다. 백엔드는 이 404를 `no_evidence`, 원문 그대로의 improvedPrompt,
빈 changes로 변환했다. 웹의 변경 없음 안내는 이 응답을 정상적으로 반영한 것이다.
후속 턴에는 history가 있어 같은 검색 결과에서도 AI 생성이 진행됐다.

첫 턴 전용 404 분기를 제거해 검색 근거가 없어도 첫 턴부터 기존 생성기를 호출한다.
검색 임계값·모델·인덱스·백엔드/웹 규약은 그대로 사용한다. 기법 sources가 없으면
백엔드가 계속 `no_evidence`로 표시하므로 근거 있는 응답이라고 주장하지 않는다.
관련 예시만 발견된 경우에도 이제 첫 턴 생성에 사용할 수 있다.
생성 실패는 기존 503이며 검색 DB 실패를 빈 결과로 숨기지 않는다.
이 변경은 이전에 생성하지 않았던 첫 턴에도 공급자 호출 비용이 발생하게 한다.
usage 반환과 모델 품질 개선은 별도 작업이다.

## 검증과 배포

- 실제 query 함수를 호출하는 회귀 테스트 6개 통과. 모델·DB·공급자·HTTP 라우팅은 모의 처리.
- 기존 응답 파싱 검사 43개 통과. 실제 LLM/배포 결과는 아직 검증하지 않았다.
- 원래 코드로 회귀 테스트 실행 시 첫 턴 생성 등 실패, 수정 코드로 전부 통과.
- `RAG query regression` CI에서 경량 의존성으로 반복 실행한다.
- PR 병합 후 **rag-server가 수정 커밋을 포함하는 브랜치로 배포됐는지** 확인한다.
  백엔드만 재배포해서는 이 수정이 적용되지 않는다.
- 새 대화(history 없음)에서 회의록 프롬프트를 요청하고 Network의 improvedPrompt와
  실제 화면이 일치하는지 확인한다. 기존 대화 재조회는 저장된 과거 결과를 보존한다.
- 참고 자료가 없는 생성이 가능해졌다는 의미이며, 모든 입력의 개선 품질을 보장하지 않는다.
