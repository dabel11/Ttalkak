# feat: 회원 사용량 한도 준비 및 인증·결제 운영 검증 보강

회원 토큰 사용량은 기록되지만 한도 정보와 요청 차단이 없어, FREE/PRO 한도를 설정할 수 있는 구조와 사용량 API를 추가했습니다. 한도는 기본 비활성이며 양쪽 숫자를 확정한 뒤 활성화합니다. AI 사용량 누락 시 성공 답변을 보존하고 사용량 불확실성을 기록합니다.

- DB lease로 회원별 진행 중 요청을 조정하고, 저장 결과 재조회는 한도 검사 전에 처리합니다.
- used/limit/remaining/limitReached/quotaEnforced/usageAvailable/usageBlocked/resetsAt을 기존 사용량 API에 추가합니다.
- 다른 작업자가 확정한 결제의 늦은 거절 응답이 갱신을 끄는 문제를 보강합니다.
- 웹 인증 정규화·상태에 provider를 보존하고 SQL 출력 기본값을 비활성화합니다.
- MySQL 컨테이너 CI에 회원 사용량·재조회·누락 차단·재시작·세션·비밀번호 변경 확인을 추가합니다.
- 읽기 전용 배포 점검 스크립트, 추가 테이블 SQL, 운영 점검 SQL, 한도·복구·배포 절차를 제공합니다.

검증: 웹 단위 테스트 238개, 배포 점검 스크립트 테스트 4개, Java 17 구문 파싱, Python/Node 구문 검사 및 diff 공백 검사 통과. 로컬 Gradle 다운로드는 네트워크 제한으로 실패했고 Docker가 없어 JUnit·MySQL 컨테이너 검증은 미실행입니다. draft PR의 CI 통과 전 병합하지 않습니다.

한도에 가까운 요청은 실행 후 실제 토큰을 기록하며, 한도를 넘긴 다음 요청부터 차단합니다. lease 만료 후 장기 정지한 작업자의 실행까지 완전히 차단하는 fencing 및 공급자 비용 원장은 포함하지 않습니다. 실제 RAG usage 반환, 팀의 한도 정책, 배포·메일·Google·Toss 검증과 기존 DB 복원 확인이 필요합니다. 새로운 lease 테이블은 추가 변경이며 기존 스키마의 전체 baseline 마이그레이션은 별도 작업입니다.
