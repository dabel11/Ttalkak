## 3. 브랜치에서 준비한 구현

- `MEMBER_REQUEST_QUOTA_ENABLED` **기본 false**: 승인 전 횟수 차단을 자동으로 켜지 않는다.
- `FREE_REQUEST_LIMIT` 기본 10, `PRO_REQUEST_LIMIT` 기본 150: **후보값**이며 실제 제공량 확정이 아니다.
- `MemberRequestGuard`가 실제 집계된 `snapshot.requests()` 기반으로 한도를 검사한다. 기존 토큰 한도 검사는 별도로 유지한다.
- `/api/me/usage`에 `requestLimit`, `requestRemaining`, `requestLimitReached`, `requestQuotaEnforced` 추가. 비활성화 시 `requestLimit`/잔여횟수는 null이다.
- 프론트는 서버가 요청 한도 활성화를 보고했을 때만 요청 횟수/잔여횟수를 노출한다.
- Spring은 RAG `/query`에 `request_id`를 보내고 같은 요청 키로 LLM 사용량을 저장한다. 비회원/요청 키 없는 신규 호출도 서버가 식별자를 만든다.

### 중요한 한계와 출시 조건

1. `rag-server/app/core/usage.py`의 `summary/records`는 **LLM 토큰만** 집계한다. Jina 리랭크 8,297토큰은 `MemberTokenUsage.totalTokens`에 포함되어 있지 않다. Jina와 LLM을 합쳐 회원 토큰 차감을 계산해서는 안 된다.
2. 현재 요청 횟수는 `member_token_usage`에 저장된 **LLM 사용량이 있는 호출 + 실제 RAG 404(no-evidence) 호출** 기준이다. RAG 404는 LLM 토큰을 만들어 넣지 않고 요청 1건으로만 기록한다. `usage=null`인 정상 응답은 누락으로 표시하고 회원 신규 호출을 보류하는 기존 보호 로직을 유지한다. 5xx/타임아웃/부분실패, 리트라이, 서버 재시작, 동시 요청의 실제 공급사 과금 대비 차감 규정은 추가 검증이 필요하다.
3. Jina 비용은 요청별 청구 토큰과 금액을 아직 Spring DB에 별도 적재하지 않는다. 요금원가 리포팅을 위해 RAG 계약과 데이터 스키마를 별도 확정해야 한다. AI 담당자 코드 임의 수정 금지.
4. 개발 브랜치만 변경. **토스 테스트 결제 기본값 4,900원, Railway 환경변수, 실제 결제, 공개 가격 UI, 자동 갱신은 변경하지 않는다.**
5. 팀 승인 후 가격/월 제공량을 다시 확정하고, `PRO_MONTHLY_PRICE_KRW`, API 응답·프론트 공개 표시·결제 테스트·실결제 준비는 별도 검증한다.
