## 2. 판정 기준 합의 (11-06)
사람 지침과 **판정기 프롬프트에 같은 문장**을 넣었다(`req-v1` → `req-v2`). 기준이 다르면 κ 가 '기준 차이'를 잰다.
- 문체·길이는 요청이 명시했을 때만 본다
- 글자 수는 공백 포함, 줄 수는 줄바꿈 기준(화면 자동 줄바꿈 제외)
- 한 항목에 모순된 값이 둘 이상이면 '아니오'(예: up_36 제출일 9/22와 9/21)

## 3. 사람 대조 시트 (11-06 ~ 11-09)

| 바꾼 것 | 왜 |
|---|---|
| 마크다운 2개 파일 → **사람당 Word 1개**(요청·결과물·질문·답이 한 페이지에) | 질문과 답이 다른 파일이라 95개를 번호로 맞춰야 했다 |
| 문항마다 **x1 질문** 추가 — "요청에 없던 걸 덧붙였는데 틀렸나" (95 → 115문항) | up_01 "7월 15일(금)"(실제 수요일)이 어느 질문에도 안 걸렸다. 충족률과 **따로** 집계 |
| 결과물 고정폭 글꼴 + 원본 기호 안내 | `**`·`|`·`#` 가 꾸밈인지 글자인지 헷갈렸다 |
| 질문표를 한 덩어리로 묶고, 결과물 상자 제거 | 표가 페이지 사이에서 끊겼고, 85줄짜리 결과물은 상자 테두리가 잘렸다 |
| κ 를 **분류별**로(객관 71 · 주관 6 · 정답 18) | 주관 질문의 낮은 일치도가 객관 질문을 끌어내린다. 결론에 쓰는 숫자는 '객관'의 판정기–사람 κ 하나 |

**받지 않은 제안**: 주관 질문 문구를 미리 구체화하기 — κ 가 바로 그 모호함을 찾는 장치라, 미리 고치면 잴 대상이 사라진다. 팀원도 동의.

## 4. Gemini 경로 (11-11)

| 전 | 후 |
|---|---|
| 본 측정의 결과물 실행·판정이 Groq 고정 | `GEN_PRIMARY` 를 따르고 `--backend` 로 고정 가능. Gemini 는 OpenAI 호환 엔드포인트로 붙여 **판정기 코드는 그대로** |
| Gemini 모델명을 적을 곳이 없었음 | `generator.default_model` 이 단일 출처(`gemini-2.0-flash` 는 이 계정에서 호출 불가) |
| 사람 대조 판정·결함 판정 검증도 Groq 고정 | 같은 백엔드를 따른다 — **본 측정과 같은 판정기를 검증**해야 κ 가 의미 있다 |
| 판정 모델이 섞여도 모름 | 보고서가 경고, 사람 대조 판정 파일은 모델이 다르면 거부 |

**실호출 확인**: 세 조건(raw·rewrite·딸깍) 모두 Gemini 로 완주 — 딸깍은 검색 7건 → 개선 프롬프트 → 실행 → 판정 오류 0. 기록당 25~32초.
**결함 판정기 검증(Gemini)**: 조정용 9/9·12/12, 별도 검증 1차 3/3·12/12, **별도 검증 2차 9/9·51/51·일관성 20/20** (같은 표본 Groq: 3/9·47/51·19/20). Groq 가 3회 모두 놓친 미묘한 변경(up_15 '한국은행', up_16 '오늘 중으로')을 3/3 잡고 오탐 0. 단 그 두 건이 결함이라는 라벨 자체가 2번(경계 사례) 사람 확인 대상이다
