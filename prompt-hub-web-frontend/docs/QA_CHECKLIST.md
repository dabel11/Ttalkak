# TTALKAK Frontend QA Checklist

이 문서는 `jaewon7025/web-demo-preview` 브랜치를 백엔드와 함께 검수할 때 사용할 체크리스트입니다.

## 실행 전 준비

- Backend: `http://localhost:8080`
- Frontend: `http://127.0.0.1:4173`
- Browser DevTools: Network 탭 열기
- Network 필터에서 `localhost:8080` 또는 `/api` 요청 확인

백엔드가 꺼져 있어도 프론트 화면은 데모 데이터 fallback으로 동작합니다. 백엔드 연동 확인 시에는 상단 상태 배지가 `Backend 연결됨`인지 확인합니다.

## Home

- 새로고침 시 `GET /api/prompts`가 200으로 응답하는지 확인합니다.
- 새로고침 시 `GET /api/tags/popular`가 200으로 응답하는지 확인합니다.
- 검색 범위를 `전체`, `해시태그`, `키워드`, `작성자`로 바꿔도 입력값이 깨지지 않는지 확인합니다.
- 추천 태그 또는 카드의 태그를 클릭하면 해시태그 검색 결과로 이동하는지 확인합니다.
- 카드의 작성자 닉네임을 클릭하면 작성자 검색으로 이동하는지 확인합니다.
- 프롬프트 상세 모달이 열리고, 모달 바깥 클릭으로 닫히는지 확인합니다.

## Auth

- 로그인 성공 후 `ttalkak_access_token`이 localStorage에 저장되는지 확인합니다.
- 로그인 후 보호 API 요청에 `Authorization: Bearer ...` 헤더가 붙는지 확인합니다.
- 토큰이 없거나 만료되어 401이 오면 로그인 팝업이 열리고 토큰 상태가 정리되는지 확인합니다.
- 권한이 없는 요청에서 403이 오면 권한 없음 안내가 뜨는지 확인합니다.
- 회원탈퇴는 `DELETE /api/auth/withdraw`를 호출하고, 성공 시 토큰과 로그인 상태가 초기화되는지 확인합니다.

## Make

- Make 진입 시 `GET /api/make/threads`가 200으로 응답하는지 확인합니다.
- Make 진입 시 `GET /api/make/folders`가 200으로 응답하는지 확인합니다.
- 프롬프트 전송 시 `POST /api/prompts/improve`가 호출되는지 확인합니다.
- 새 대화는 서버에서 받은 `threadId` 또는 `id`를 유지하는지 확인합니다.
- 폴더 생성 후 이동 시 임시 `thread-...` 또는 `folder-...` id가 서버로 전송되지 않는지 확인합니다.
- 폴더 이동 시 `PATCH /api/make/threads/:id/folder`의 `:id`가 서버 숫자 id인지 확인합니다.
- 백엔드 요청 실패 시 화면은 데모 상태를 유지하되 안내 문구가 뜨는지 확인합니다.

## My Page

- 신규 로그인 사용자의 My page는 기본적으로 비어 있어야 합니다.
- `데모 데이터 채우기`를 누르면 QA용 샘플 보관함/댓글/신고 데이터가 나타나는지 확인합니다.
- `데모 데이터 숨기기`를 누르면 샘플 데이터가 숨겨지는지 확인합니다.
- 저장 취소는 My page 안에서 즉시 제거되지 않고, 다른 화면으로 이동할 때 확정되는지 확인합니다.
- 댓글 관리의 원문 보기, 수정, 삭제가 동작하는지 확인합니다.

## Share

- 로그아웃 상태에서 Share 진입 시 로그인이 필요하다는 안내가 보이는지 확인합니다.
- 로그인 상태에서 제목, 최종 프롬프트, 태그를 입력해 공유할 수 있는지 확인합니다.
- 태그 검색은 기존 태그를 우선 추천하고, 결과가 없을 때만 새 태그 추가 흐름을 보여주는지 확인합니다.
- 공유 후 Home 최신 정렬에서 방금 공유한 프롬프트가 보이는지 확인합니다.

## Prompt Actions

- 로그아웃 상태에서 저장, 좋아요, 댓글, 답글, 신고, 공유, 폴더 관리가 로그인 팝업으로 연결되는지 확인합니다.
- 로그인 상태에서 저장/좋아요/댓글/답글/신고가 해당 API를 호출하는지 확인합니다.
- 본인이 작성한 댓글/답글에는 신고 대신 수정/삭제가 보이는지 확인합니다.
- 다른 사용자의 댓글/답글에는 좋아요/신고가 보이는지 확인합니다.
- 답글이 있는 댓글을 삭제하면 원댓글 자리에 `삭제된 댓글입니다.`가 남는지 확인합니다.

## Admin

- 로그인 후 `관리자 데모`를 켜야 Admin 메뉴가 보이는지 확인합니다.
- Admin 모드에서는 Home/Make/My page/Share 같은 일반 사용자 메뉴가 숨겨지는지 확인합니다.
- 신고 관리에서 원문 보기, 수정 요청, 게시글 숨김, 검토 완료, 기각, 재처리, 대상 삭제가 구분되는지 확인합니다.
- 댓글 신고 원문 보기는 해당 댓글을 강조하는지 확인합니다.
- 프롬프트 관리에서는 관리자가 직접 사용자 글을 수정하지 않고 수정 요청/숨김/삭제 중심으로 동작하는지 확인합니다.
- 태그 관리에서 검색, 상태 필터, 정렬, 검토 완료, 재검토, 추천 제외가 확인되는지 확인합니다.

## Known Partial Areas

- 화면은 여전히 optimistic local state를 먼저 갱신합니다. 서버 실패 rollback은 다음 연동 단계에서 보강해야 합니다.
- Google OAuth2 버튼은 실제 OAuth가 아니라 데모 흐름입니다.
- Admin 권한은 프론트 데모 토글로 확인하지만, 실서비스에서는 반드시 서버 권한으로만 결정해야 합니다.
- Make thread delete는 현재 백엔드 계약에 없는 로컬 전용 동작입니다.
